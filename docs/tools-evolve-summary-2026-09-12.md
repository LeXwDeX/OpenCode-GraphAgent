# Tools 输出契约修订记录

本轮按 AHE 方法处理两个有直接源码/回归证据的文本问题。范围限定为内部工具的贴身描述与输出，不修改全局角色、用户 Memory 或系统提示词。

## 组件地图与评估

- Router / policy：选择编排方式与深度，存在过度固定波次的设计疑问，未在这次文本修复中改动。
- 工具 schema / leaf：拥有参数含义、执行范围和错误行为。
- 截断输出契约：拥有正文位置、截断事实和继续读取入口；不应因可用工具名单而接管编排决策。
- Goal 自动来源：由运行时 synthetic 标记修复，不能通过给 Memory 添加更多提示来弥补。

## 失败模式

### P1：结果读取越过边界，替父 Agent 决定委派

证据：`packages/opencode/src/tool/truncate.ts` 原来在 task 权限可用时输出 `Do NOT read the full file yourself - delegate to save context`；已有测试要求提示包含 `Task tool`。同样的短期文件，权限不同就强制不同的任务分解。这与用户减少 Agent 重复劳动、按需读文件的要求冲突。

根因：工具输出契约混入工作流指导。具有委派权限不等于需要新增子任务。

### P2：参数描述与实际目标不一致

证据：legacy Grep 的 path 描述仅写 directory，但代码接受文件路径；缺失 `file` 参数使真实单文件搜索扩展到兄弟文件。测试中目标和兄弟文件含相同关键词，修复前返回 2 个匹配而非 1 个。

根因：叶子丢失路径类型，文本又没有准确描述文件入口。这里以修代码为主，不能只改提示。

## 变更清单

### chg-1：截断只返回文件读取契约

- 失败证据：P1 的实际输出分支及用户减少重复委派的明确要求。
- 根因：`hasTaskTool` 把权限可用性当编排决策。
- 最小修复：所有调用者统一保留完整文件路径及 `Grep` / `Read with offset/limit` 提示；删除强制委派分支。保留接口第三参数，避免为这次文本变更批量修改调用者。
- 预测：翻转的是“工具结果强制再委派”的约束；Agent 可以直接读取所需片段。文件落盘、大小上限、保留时间不变。真实模型是否少发 task 调用尚未测量。
- 风险：模型可能自行读太多内容；现有有界预览与分页方式仍可用，后续用真实任务验证读取范围，不能以增加强制委派命令补偿。
- 组件层级：工具输出契约。

### chg-2：Grep 描述允许精确文件目标

- 失败证据：P2 的真实文件夹回归；不存在路径原先还会退回父目录搜索。
- 根因：path 类型信息未传入底层 Ripgrep。
- 最小修复：显式文件传 `file: basename`；无法访问的目标报错；path 描述从 directory 改为 file or directory。
- 预测：命名文件只返回该文件的匹配，缺失目标不再产生误导性的兄弟文件结果；目录和 include 行为保持。
- 风险：依赖“缺失路径自动扩大范围”的调用者现在收到错误，这是有意收紧；应修正路径而不是静默扩大检索。
- 组件层级：工具参数描述；行为修复属于同一 leaf。

## 验证与证伪

- Truncation：19 测试通过，包含允许委派时仍可按需读取完整落盘内容，以及没有 Task 强制指令。
- Grep：8 测试通过；精确文件/缺失路径先红后绿，目录 include 与 alias 权限用例仍通过。
- 新旧文本不是模型调用减少的直接证明。下一次真实任务比较：短日志定位、长测试报告定位、报告文件与兄弟文件同名关键词；记录新建子任务次数、读取量和答案证据是否完整。
- 如果 chg-1 在这些任务上增加总消耗且不改善质量，重新评估或回滚这项输出指导修改；不要堆叠更多命令式规则。
- 未处理的固定 DAG 深度和大范围模板政策见 [核心产品报告](core-product-review-2026-09-12.md)，需要独立的实际任务质量对照。
