## 1. 范围与结论

本步把 S01–S04 已定义的折叠契约接入 OpenCode 的普通 conversation 请求，并在 AI SDK 的 provider message transform 之后、Native 的 canonical message conversion 之后验证和投影。折叠只作用于本次发送使用的独立 wire 副本，不回写会话数据库、调用输入、结果正文、metadata 或调用顺序。

候选只接受已由当前运行时成功结算并在有界 ledger 中证明为 `host-builtin` 的 `read`、`grep`、`glob`。custom、MCP、provider 同名工具，来源缺失或旧 generation，截断/provider-executed 结果，动态指令、指令状态缺失或未知，以及非 conversation purpose 都保守跳过。`read` 的 `metadata.loaded` 必须是可识别的字符串数组；非空数组、hook/plugin/system-reminder 注入均标记为动态指令。

本步不包含 Core runner 接线（S06）、外部 DCP 插件识别和迁移诊断（S07）、旧路径退役或后续发布工作。当前仓库也没有可供这个隔离运行时切片独立发布的测试环境，因此没有部署声明；本分支只推送给父任务独立复审，且没有启动 S06。

## 3. 关键正式回归

`context-folding.test.ts` 直接验证两种 wire adapter：

- `projects the AI SDK final provider-visible request without mutating stored messages`
- `projects canonical Native messages before executable definitions are added`
- `fails closed when bound history metadata evidence changes`
- `fails closed when final AI SDK input, body, outer fields or order differ from the bound history`
- `fails closed for a full-request visible ID collision across different tool names`
- `fails closed when final Native input, body or order differs from the bound history`
- Claude/Mistral 非碰撞 ID 继续走正向，共享 scrub 发生碰撞时保守跳过。

`llm.test.ts` 验证 AI SDK 与 Native 的真实发送边界只折叠 wire 副本，并覆盖配置关闭及 `OPENCODE_DISABLE_PRUNE`。`tool-source-ledger.test.ts` 验证来源隔离、generation 失效、有界性、动态/未知指令、来源缺失和 custom/MCP/provider 覆写。`prompt.test.ts` 提供上表 A04 的两种完整正向闭环和两个真实同名覆写失败闭环。
