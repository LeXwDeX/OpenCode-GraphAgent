## Acceptance evidence

### Persistent prune retirement and historical marks (I10)

- `SessionCompaction.Interface` no longer exposes `prune`; the implementation and clean-exit call in
  `session/prompt.ts` were removed. A direct service-shape regression test asserts that the entry point is absent.
- `MessageV2` historical `state.time.compacted` decoding and serialization were left intact. The existing
  `replaces compacted tool output with placeholder` regression passed.
- Context-folding history continues to require `time.compacted === undefined` before a result is complete, so an old
  marked result cannot become a witness. No new production assignment to `time.compacted` remains in the session
  runtime.
- Manual full compaction passed with `compaction.dynamic: false`. Automatic full compaction settings remain separate.

### Exact external DCP state (I09)

The real server-plugin loader tests cover:

- exact npm or file package identity plus a successfully registered context-folding hook -> `loaded`;
- exact DCP with `enabled: false` or `dtc.enabled: false` returning empty hooks -> `unknown`, leaving the built-in
  implementation eligible and emitting no migration notice;
- a retained transform from a partially failed legacy apply -> `loaded`, preventing two active transformations;
- once-per-instance warning state and re-notification after instance disposal/recreation;
- exact package apply failure, install failure, substring package, legacy file without package metadata, and pure mode
  -> `unknown`, with no migration notice.

OpenCode supplies this state to `ConfigCompaction.resolveDynamic`. Core runner has no server-plugin capability and
keeps the state explicitly `unknown`. Unknown third-party message rewriters remain an operator-managed compatibility
boundary, documented in [migration.md](../migration.md).

Actual loader-to-LLM outbound tests cover both AI SDK and Native runtimes. An active exact DCP makes built-in folding
retreat; both DCP-disabled paths, an apply failure, and a non-DCP transformer preserve normal built-in folding. Two
requests through one active instance produce exactly one migration warning.

### Safe diagnostics (I12)

The shared diagnostic builder accepts only aggregate policy and projection structures. Its exact-key regression
asserts that messages, tool arguments, paths, fingerprints, and embedded reference identifiers do not appear. Missing
token estimates, target, over-budget state, group counts, and exclusion counts stay `unknown`, not zero.

Captured OpenCode test logs demonstrate both runtimes:

- enabled request: `applied=true`, one duplicate group and one folded output, with measured before/after/savings;
- disabled request: `enabled=false`, `skipReason=disabled`, unchanged outbound body, and unknown token estimates;
- non-conversation request: `skipReason=non-conversation` and unknown estimates.

Core runner resolves layered configuration per provider turn, logs the same safe aggregate, and never manufactures a
plugin state it cannot observe.
