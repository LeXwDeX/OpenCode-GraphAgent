## 1. 范围与结论

本步把 S02/S03 的共享规划、预算和原子投影接入 Core 普通 conversation runner。投影发生在完整 `LLM.Request` 建立后、现有 `compactIfNeeded` 前；摘要仍读取原始 entries，最终发送只使用独立投影请求，不回写会话存储、工具结果或下一轮历史。

Core 新增有界、实例内存型执行来源台账。实际 application 注册记录为 `custom`，location/local 注册记录为 `host-builtin`；每次 materialize 激活有效注册集合及 generation，只有该集合中实际成功结算的调用才入账。同名 local override、缺失记录、generation 变化和新实例重启前历史均失败关闭，不能仅凭工具名放行。台账不保存参数、正文、路径、指纹、计划或跨请求内容缓存。

内置 `read` 只接受完整且字段精确的 `ReadTool.TextPage`：正文为 `content`，`type/mime/offset/truncated/next`、完整输入、metadata 及持久化外层字段均绑定。投影只替换最终 provider wire JSON 中唯一 `content` 槽位，并在投影前后各执行真实 route preparation，验证 provider route/protocol、call/result 配对、顺序、输入、witness 和除选中正文外的全部 wire 值未变。list、media、binary、截断页、未知结构、动态指令、provider-executed、失败或运行中结果均保护。

本步没有实施 S07 的旧清理入口退役、外部 DCP 插件识别和迁移诊断，也没有实施 S08–S10 的真实宿主、性能、CI 或测试环境交付。当前切片没有独立可发布测试环境，因此没有部署声明；即使门禁通过，仍只标记为“待父任务审计”。

## 3. 可证伪验收

### I02：真实 Core runner 闭环

正式测试 `SessionRunnerLLM hot path > folds duplicate built-in read, grep, and glob outputs only in the final outbound request` 从真实 Core runner 依次执行两次 builtin read、grep、glob，经注册、实际结算、来源台账、持久化历史和下一次普通请求进入真实 OpenAI-chat route body conversion。断言三个旧结果均在最终 outbound body 中折叠，三个较晚 witness 保持完整；再次读取会话存储并逐项确认六个原始工具记录的输入、结构化结果、正文、身份及顺序完全不变。

### I13/I14：TextPage 正向与未知结构保护

- `accepts only complete exact TextPage pairs and binds every outer field`
- `rejects list, binary, media, failed, running, dynamic, and unknown-instruction results`
- `rejects captured history after input, body, metadata, order, deletion, or cross-tool ID mutation`
- `projects only conversation requests and leaves disabled, compaction, auxiliary, and unknown purposes untouched`

正向用例使用真实 `new ReadToolFileSystem.TextPage(...)`，验证仅 `content` 改为固定占位，JSON result 类型及全部外层字段不变。负向 fixture 覆盖外层字段/类型/额外字段差异、截断、list、media、binary、未知 shape、动态或未知指令、失败/运行中状态；最终 input、body、metadata、持久化外层字段、顺序、删除或跨工具 ID 碰撞任一变化都返回未投影。

### U23：来源身份

- `records actual application and local settlement provenance and invalidates overridden history`
- `fails closed for missing provenance and invalidates recorded history after a generation change`
- `does not trust pre-restart history in a fresh provenance ledger`

这些测试经过真实 ToolRegistry materialization/settlement，而不是直接伪造 planner 的 `host-builtin` 输入。
