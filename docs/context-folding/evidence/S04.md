## 2. 配置与兼容契约

解析器使用以下有效值优先级：

| 条件                         | `configured` | `source`      | 兼容说明                                                                   |
| ---------------------------- | ------------ | ------------- | -------------------------------------------------------------------------- |
| `OPENCODE_DISABLE_PRUNE`     | `false`      | `environment` | 最高优先级；OpenCode 合并结果同时显式置 `dynamic:false` 与旧 `prune:false` |
| 显式 `dynamic`               | 原值         | `dynamic`     | 新字段覆盖冲突的旧字段                                                     |
| `dynamic` 缺失且显式 `prune` | 原值         | `prune`       | 仅作为旧配置回退，并标记 `deprecatedPrune:true`                            |
| 两字段均缺失                 | `true`       | `default`     | 解析时默认开启，不在 schema 或合并对象中制造字段                           |

`OPENCODE_DISABLE_AUTOCOMPACT` 仍只设置 `compaction.auto:false`，不改变 `dynamic`；反之 `OPENCODE_DISABLE_PRUNE` 不改变 `auto`。V1 schema、Core V2 schema 和迁移均保留显式 `dynamic`，旧 `prune` 描述改为 deprecated fallback，但没有添加会吞掉“缺失”语义的 schema default。

外部插件状态由调用方以 `knownExternalDcp: "unknown" | "loaded"` 提供。只有在运行时已正向识别为 `loaded` 时，解析器才保留用户的 `configured` 意图、将内置 `enabled` 置为 `false` 并返回 `skipped:"external-dcp"`；`unknown` 不被解释为已加载或未加载。准确加载态和一次性迁移诊断仍留 S07。
